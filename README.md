# Jarvis — ядро личного ассистента

Один «мозг» на Claude Agent SDK, память в Obsidian-vault, клиенты — Telegram, голос на ПК и приложение
(Tauri 2 + Vue 3: Windows, macOS, Android; то же приложение открывается в браузере).

## Запуск

```bash
uv sync
cp .env.example .env    # заполнить ключи
uv run uvicorn jarvis.api:app --host 127.0.0.1 --port 8000
```

Минимум в `.env`: `ANTHROPIC_API_KEY`, `JARVIS_VAULT`, и либо `TELEGRAM_BOT_TOKEN` +
`TELEGRAM_ALLOWED_IDS`, либо `JARVIS_API_TOKEN`. Свой Telegram ID бот подскажет сам в ответ на
первое сообщение.

Vault создаётся при первом запуске. Чтобы добавить проект, скопируйте
`10_Projects/_template.md` в `10_Projects/<id>.md` и заполните frontmatter.

## Что умеет

- Отвечает по реестру проектов (сводка — в системном промпте, подробности — `project_registry`).
- Читает, ищет и правит заметки vault; быстрые заметки — в `00_Inbox/`.
- Память между разговорами — `90_Agent/memories/`.
- Одна сессия на пользователя, общая для всех клиентов; `/new` начинает заново. После паузы в полчаса
  (`JARVIS_SESSION_IDLE_MIN`) сессия начинается заново сама — см. «Сколько стоит ход».
- Telegram: текст и голосовые до 30 с (Yandex SpeechKit).
- Журнал: SQLite (`/journal`) + дневная заметка `40_Journal/ГГГГ-ММ-ДД.md`.
- Сценарии: фраза или время запускают цепочку действий без модели — см. «Сценарии».

## Границы безопасности

- Из встроенных инструментов агенту доступны только Read/Glob/Grep/Write/Edit. Shell нет; в интернет
  ходит не сам агент, а отдельный помощник без доступа к заметкам — см. «Браузер».
- Файлы на ПК — только найти, открыть и (с подтверждением) напечатать, и только в `JARVIS_OPEN_ROOTS`. Windows-MCP (PowerShell,
  управление окнами) намеренно не подключён: ему нужен поток подтверждений, это этап 5.
- PreToolUse-хук (`jarvis/agent.py: check_path`) отклоняет любой путь вне vault и запись в
  `90_Agent/policies.md`, `.obsidian/`, `.git/`, а также в `50_Scenarios/`: сценарии агент меняет
  только инструментом `scenario_save`, после вашего подтверждения.
- GitHub MCP подключается только при заданном `GITHUB_TOKEN`, в режиме read-only.
- HTTP API слушает localhost; наружу его не выставлять (дальше — Tailscale).

## Голос на ПК (этап 2)

```
микрофон → Silero VAD режет речь на фразы (на ПК) → WebSocket /voice/ws
         → STT (GigaAM, Whisper или SpeechKit) → есть обращение «Джарвис, …»? нет — фраза отброшена
         → Haiku 5.5 (быстрый ответ или delegate)
                                                    └→ агент на Sonnet 5.5 (vault, файлы на ПК)
         ← озвучка SpeechKit по фразам: первая звучит, пока генерируется вторая
```

Клиент тонкий: ключи Anthropic и SpeechKit есть только у ядра. История разговора общая
со всеми каналами — можно начать в Telegram и продолжить голосом.

Запуск клиента (ядро уже запущено, в `.env` тот же `JARVIS_API_TOKEN`):

```bash
uv sync --extra voice
uv run --extra voice python -m jarvis.voice_client
```

- «Джарвис, включи свет» одной фразой — сигнала ждать не нужно. Имя может стоять и в конце
  («включи свет, Джарвис»), и в середине («скажи, Джарвис, который час»). Если сказать только
  «Джарвис» — прозвучит сигнал, и 5 секунд клиент ждёт команду. Enter — то же без слов.
- После ответа 5 секунд слушает продолжение без обращения.
- Слова активации задаёт ядро: `JARVIS_WAKE_WORDS=джарвис` (через запятую, можно фразы из нескольких
  слов: `окей дом`). Первое слово — имя ассистента: так он себя и называет. Модель под новое слово
  обучать не нужно: обращение ищется в распознанном тексте.
- Сравнение идёт по звучанию: «Клод», «Клот», «Клотт» и «Clod» — одно слово. Имя от семи букв
  дополнительно прощает две ошибки («Жарвис», «Джервис»), от пяти — одну, короче — ни одной: рядом
  с «клод» стоят «код» и «кот». Поэтому длинное имя надёжнее. На синтезированных фразах с фоном
  этого микрофона «Джарвис» узнан 100 раз из 100, «Клод» — примерно 7 раз из 10: в шуме он звучит
  как «плот», «флот», «клут». Такие слова можно дописать в список: `клод, клут, плот, флот`.
  Что слышит распознавание на самом деле, показывает `--debug`.
- Так работает только своё распознавание (`JARVIS_STT_URL`): клиент присылает ядру каждую услышанную
  фразу, и через облако это значило бы отправлять туда все разговоры в комнате. Со SpeechKit
  остаётся английское «Hey Jarvis»: `--wake model` (`JARVIS_WAKE_MODE=model`); `--wake both` — оба способа.
- Перебить ответ: Enter. В режиме `model` и `both` — ещё и «Hey Jarvis». С гарнитурой можно
  `--barge-in vad`: перебивает любая речь (с колонками так нельзя — ассистент будет перебивать сам себя).
- `--debug` — печатать и фразы, в которых обращения не было: видно, что именно слышит микрофон.
- Строка текста + Enter — вопрос текстом, ответ голосом.
- `--list-devices` и `--device N` — выбор микрофона; `--threshold` — чувствительность «Hey Jarvis».
- `--mic-test` — проверка микрофона: 5 секунд тишины и 6 секунд речи, затем уровень, перегруз, во
  сколько раз голос громче фона, распознанный текст, время распознавания и услышано ли обращение.
  Запись проверки сохраняется в `data/mic-test.wav` (остаётся на этом ПК; `--mic-save ""` — не сохранять).
  Если ассистент не слышит, начните с неё. Голос громче фона меньше чем в 4 раза — усиление не
  поможет, микрофон должен быть ближе: гарнитура или колонка с микрофоном.
- Долгие задачи (дольше `JARVIS_VOICE_AGENT_TIMEOUT`) голос не держат: «пришлю в Telegram».
- Файлы на ПК: задайте `JARVIS_OPEN_ROOTS`, и «открой таблицу бюджета» найдёт и откроет файл.
  Поиск и открытие — только внутри этих папок. Работает, если ядро запущено на том же ПК.

### Речь без облака

Вместо SpeechKit можно использовать свои серверы — ядро выбирает их, если задан `JARVIS_STT_URL`
или `JARVIS_TTS_URL` (`jarvis/speech.py: make_speech`):

- STT — свой сервер `jarvis.stt_server`: русская модель GigaAM v3 через `onnx-asr`, на процессоре.
  Фразу в 2–4 секунды распознаёт за 0,2–0,3 с (Ryzen 9 4900H), на тишине текст не выдумывает.
  При первом запуске скачивает модель с Hugging Face (225 МБ). Отвечает по тому же интерфейсу, что и
  Whisper (`/v1/audio/transcriptions`), так что подойдёт и любой OpenAI-совместимый сервер:
  faster-whisper-server, speaches. Whisper `small` на том же процессоре тратит 2,4 с на любую
  фразу, `medium` — около 7 с.
- TTS — свой сервер `jarvis.tts_server` (см. «Естественный голос» ниже) или HTTP-сервер Piper.
  Ядро различает их по адресу: `JARVIS_TTS_URL`, который оканчивается на `/audio/speech`, — это
  OpenAI-совместимый сервер (свой или любой другой), иначе — Piper. Русские голоса Piper:
  `ru_RU-irina-medium`, `-denis-`, `-dmitri-`, `-ruslan-`.

```bash
uv run --python 3.13 --extra voice --extra stt python -m jarvis.stt_server   # порт 5006
uv run --python 3.13 --extra voice --extra tts python -m jarvis.tts_server   # порт 5007, Silero
uv tool install --python 3.13 "piper-tts[http]"
python -m piper.download_voices --download-dir ~/piper-voices ru_RU-irina-medium
python -m piper.http_server --host 127.0.0.1 --port 5005 -m ru_RU-irina-medium --data-dir ~/piper-voices
```

```
JARVIS_STT_URL=http://127.0.0.1:5006/v1/audio/transcriptions
JARVIS_STT_MODEL=               # нужен только Whisper-серверам, напр. Systran/faster-whisper-small
JARVIS_TTS_URL=http://127.0.0.1:5007/v1/audio/speech   # Piper: http://127.0.0.1:5005
JARVIS_TTS_VOICE=xenia
JARVIS_TTS_RATE=48000          # должна совпадать с частотой сервера: Silero — 48000, Piper medium — 22050
```

Голос включается, только когда заданы оба URL. `onnxruntime` (GigaAM, Piper, openWakeWord) пока
собран до Python 3.14 — на 3.15 ядро работает, а сервер распознавания, Piper и голосовой клиент
ставьте в окружение 3.13.

GigaAM слышит короткое «стоп» неточно («соп», «топ»): пока звенит будильник, одно слово, похожее
на «стоп», тоже его выключает. У Whisper для этого есть подсказка — она используется, если STT —
Whisper.

### Естественный голос

`jarvis/tts_server.py` — свой сервер синтеза с интерфейсом OpenAI `/v1/audio/speech`. Движок
выбирается при запуске, у каждого своё окружение. Замеры — Ryzen 9 4900H и GTX 1660 Ti.

| Движок | Где считает | Фраза в 2 секунды | Голоса | Память |
|---|---|---|---|---|
| `silero` — Silero v5 | процессор | 0,1 с | пять готовых: `aidar`, `eugene` (мужские), `baya`, `kseniya`, `xenia` | 0,8 ГБ обычной |
| `espeech` — ESpeech-TTS RL-V2 (F5-TTS) | видеокарта | 2–3,5 с | любой, по образцу до 12 секунд | 1,5 ГБ видеопамяти, 4,8 ГБ обычной |
| Piper (отдельный сервер) | процессор | 0,2 с | четыре готовых | 0,65 ГБ обычной |

Ядро озвучивает ответ по предложениям, поэтому задержка до первого звука — это время синтеза первой
фразы. С Silero звук начинается через 1,6–2 секунды после вопроса, из них синтез — 0,2 секунды.

**Подготовка текста.** Модели читают только русские буквы, поэтому сервер сначала переписывает текст
(`normalize`): числа, время, проценты, градусы и деньги — словами («в 14:30» → «в четырнадцать
тридцать», «1 минута» → «одна минута»); числа перед месяцем, годы и века — порядковыми («19 ноября» →
«девятнадцатого ноября», «в 1237 году» → «в тысяча двести тридцать седьмом году», «XIII век» →
«тринадцатый век»); латиница — русскими буквами («YouTube» → «ютуб», «USB» → «ю эс би»). Падеж
угадывается по соседним словам и иногда неверен. Ударения модели расставляют сами; знак «+» перед
гласной задаёт ударение явно.

**Silero.** Ставится набором `tts` (PyTorch для процессора — 210 МБ, модель — 139 МБ, скачивается при
первом запуске). Лицензия модели — только некоммерческое использование.

```bash
uv run --python 3.13 --extra voice --extra tts python -m jarvis.tts_server --engine silero --voice xenia
```

**Свой голос (ESpeech).** Нужна видеокарта NVIDIA и отдельное окружение: PyTorch с CUDA и модель —
около 9 ГБ на диске. Пакет `f5-tts` ставится без зависимостей: они нужны ему для обучения и
веб-интерфейса, а синтезу хватает списка ниже.

```bash
uv venv --python 3.13 ~/.local/share/jarvis/venv-clone
uv pip install --python ~/.local/share/jarvis/venv-clone/bin/python --no-deps f5-tts==1.1.22
uv pip install --python ~/.local/share/jarvis/venv-clone/bin/python torch torchaudio vocos x_transformers torchdiffeq librosa soundfile pypinyin rjieba "transformers<5" tqdm safetensors matplotlib ruaccent fastapi uvicorn httpx
mkdir -p ~/.local/share/jarvis/models/espeech-rl-v2 && cd ~/.local/share/jarvis/models/espeech-rl-v2
curl -LO https://huggingface.co/ESpeech/ESpeech-TTS-1_RL-V2/resolve/main/espeech_tts_rlv2.pt   # 2,7 ГБ
curl -LO https://huggingface.co/ESpeech/ESpeech-TTS-1_RL-V2/resolve/main/vocab.txt
```

Голос — пара файлов в `data/voices/`: `имя.wav` (3–12 секунд чистой речи одного человека, моно) и
`имя.txt` (что в записи сказано, слово в слово). Записывать и использовать чужой голос можно только с
согласия его владельца. Запуск из папки проекта:

```bash
~/.local/share/jarvis/venv-clone/bin/python -m jarvis.tts_server --engine espeech --voice имя --port 5008
```

- Время синтеза растёт с длиной образца и числом шагов (`--steps`, по умолчанию 8). Фраза в две
  секунды: образец 4 секунды — 2,1 с, образец 7 секунд — 3,5 с; 16 шагов — вдвое дольше.
- `--half` (половинная точность) экономит видеопамять, но на GTX 16xx считает в 4–5 раз медленнее.
- `transformers` нужен ниже пятой версии: с пятой RUAccent, который расставляет ударения, не работает.

В `.env` ядра — адрес, голос и частота выбранного сервера:

```
JARVIS_TTS_URL=http://127.0.0.1:5007/v1/audio/speech   # клонирование: порт 5008
JARVIS_TTS_VOICE=xenia                                 # клонирование: имя образца
JARVIS_TTS_RATE=48000                                  # клонирование: 24000
```

## Управление ПК: звук, плееры, сайты, печать, экран, браузер

`JARVIS_PC_CONTROL=1` даёт ассистенту инструменты на компьютере, где запущено ядро
(`jarvis/pc.py`, Linux с PipeWire):

- `pc_volume` — узнать и изменить громкость, выключить и вернуть звук (`wpctl`, не выше 100%);
- `pc_media` — что играет, пауза, продолжить, следующий и предыдущий трек, выключить (`gdbus`,
  MPRIS). Работает с браузером и плеерами: вкладка с YouTube или Яндекс Музыкой тоже считается
  плеером. Если играет музыка, которую включил сам ассистент, команда достаётся ей;
- `pc_open_url` — открыть сайт в браузере по умолчанию. Только `http://` и `https://`;
- `pc_youtube` — найти видео и открыть его. Поиск делает `yt-dlp` (`uv tool install yt-dlp`);
  без него или при ошибке открывается страница поиска YouTube;
- `pc_notify` — показать уведомление на экране (`notify-send`).

Голосом это выполняет Haiku за 1–2 с (YouTube — 4–5 с из-за поиска), из Telegram и чата — агент.
Открытые адреса и запросы пишутся в дневной журнал.

### Печать

«Напечатай договор» — агент находит файл в `JARVIS_OPEN_ROOTS` и вызывает `print_file`
(`jarvis/printing.py`). Перед печатью вы видите файл, принтер, число страниц и копий и отвечаете
«да» или «нет» в приложении или Telegram; без «да» в очередь ничего не уходит.

- PDF, картинки и текст печатаются как есть; docx, xlsx, odt и подобные сначала превращаются в PDF
  через LibreOffice (`soffice --headless`).
- Принтер — системный по умолчанию (`lpstat -d`) или `JARVIS_PRINTER`. Если он выключен, ассистент
  предупредит: задание встанет в очередь и напечатается, когда принтер включат.
- Можно указать копии и страницы: «напечатай первые три страницы в двух экземплярах».

### Снимок экрана

`JARVIS_SCREEN=1` даёт агенту инструмент `screen_look`: «что у меня на экране?», «прочитай, что тут
написано», «что значит эта ошибка?» (`jarvis/screen.py`). По умолчанию выключено.

- На Wayland программа экран не видит: снимок делает сам рабочий стол через портал и показывает на
  экране вопрос о разрешении. Ответить нужно за компьютером; запоминает ли GNOME ответ для службы
  ядра — не проверено.
- Снимок уменьшается, уходит модели и сразу удаляется с диска; в журнал пишется только сам факт.
- Агент делает снимок только по прямой просьбе. На экране бывают пароли и переписка: картинка
  уходит в Anthropic API так же, как текст разговора.
- Нужен системный `python3-gi` (в Ubuntu с GNOME он есть).

### Браузер

`JARVIS_BROWSER=1` даёт агенту инструмент `browser_task`: «посмотри в интернете, сколько стоит…»,
«найди расписание…», «заполни заявку на сайте…» (`jarvis/browser.py`). Нужен Playwright MCP — он
ставится отдельно, вне репозитория, и использует установленный Chrome:

```bash
npm install --prefix ~/.local/share/jarvis/browser --save-exact --ignore-scripts @playwright/mcp@0.0.84
```

По сайтам ходит не сам агент, а отдельный помощник на быстрой модели (`JARVIS_BROWSER_MODEL`, по
умолчанию модель роутера). У него есть только браузер: ни заметок, ни файлов, ни дома, ни Notion.
Агент передаёт ему поручение словами и получает обратно текст. Так устроено по трём причинам:

- страница может подсунуть свой текст как указание. Помощнику нечего увести: он знает только
  поручение. Его ответ агент получает с пометкой, что это данные, а не указания;
- снимки страниц большие. Они остаются в разовой сессии помощника и не попадают в разговор агента;
- быстрая модель дешевле. Живая проверка («столица Австралии по Википедии и её население») заняла
  20 с и стоила 4 цента, из них помощник — меньше цента.

Что ограничено механически:

- у браузера свой профиль Chrome (`~/.local/share/jarvis/browser/profile`) без ваших входов. Если вы
  сами войдёте в нём на каком-то сайте, помощник сможет действовать там от вашего имени;
- выполнение скриптов на странице, загрузка файлов с диска, снимки и сохранение в файлы выключены;
- адреса этого компьютера и домашней сети закрыты: и по команде помощника, и по ссылке со страницы
  (правила `--host-rules` Chrome), вместе с адресом Home Assistant. Имя в интернете, которое ведёт
  на домашний адрес, этим не закрывается;
- текст вводится в одно поле на страницу — это поиск. Любая форма заполняется одним вызовом: вы
  видите все значения и отвечаете «да» или «нет». Поля с паролем, кодом и данными карты помощник не
  заполняет вовсе;
- нажатия вроде «Оплатить», «Отправить», «Удалить», «Принять» — с подтверждением. Кнопка
  опознаётся по надписи на самой странице и по описанию помощника; это страховка от ошибки, а не
  преграда для страницы, которая назвала кнопку иначе;
- проверку «я не робот» помощник не проходит: останавливается и сообщает.

Окно Chrome видно на экране, пока идёт поручение; `JARVIS_BROWSER_HEADLESS=1` прячет его, но тогда
поисковики требуют проверку «я не робот». Ищет помощник через Bing (`JARVIS_BROWSER_SEARCH`): на
19.11.2026 только он отдаёт результаты браузеру под управлением программы — Google, Яндекс,
DuckDuckGo, Brave и Startpage показывают проверку. На одно
поручение — не больше 25 шагов и `JARVIS_BROWSER_BUDGET_USD` (0.3). Действия помощника пишутся в
журнал ядра (`web`, `web_denied`), поручение — в дневной журнал.

Остаточный риск: ответ помощника составлен по страницам, и вредная страница может попытаться через
него повлиять на агента. Агенту сказано не выполнять просьб из такого текста, но это уже не
механическая граница.

## Сколько стоит ход

Агент (Sonnet) в каждом запросе заново отправляет описания своих инструментов — около 13 тысяч
токенов. Кэш запроса живёт пять минут, поэтому:

- ход после паузы — примерно 3,5 цента;
- следующий ход в пределах пяти минут — меньше цента;
- чем длиннее сессия, тем дороже ход после паузы: за три дня одной сессии он вырос с 3 до 5 центов.

Поэтому после `JARVIS_SESSION_IDLE_MIN` минут тишины (30; 0 — никогда) агент начинает новую сессию
и получает короткую справку: последние шесть реплик за последние шесть часов. Память в vault при
этом на месте. Команды голосом, которые выполняет сама быстрая модель (свет, громкость, таймеры,
музыка, сценарии), агента не трогают и стоят доли цента.

`cost_usd` в ответе `/chat` и в журнале — цена именно этого хода вместе с браузером. Agent SDK
сообщает цену сессии нарастающим итогом, ядро вычитает прошлый итог.

## Музыка

«Клод, включи Кино», «включи что-нибудь спокойное», «что играет?», «пауза», «дальше», «выключи
музыку», «включи на станции джаз» (`jarvis/music.py`). Голосом это делает Haiku одним запросом.

- **YouTube на ПК** — включается вместе с `JARVIS_PC_CONTROL=1`, аккаунт не нужен. `yt-dlp` находит
  пять видео по запросу, `ffplay` играет только звук, без окна. Очередь, пауза и «дальше» — свои;
  пауза запоминает секунду и продолжает с неё.
- **Яндекс Музыка на ПК** — если задан `YANDEX_MUSIC_TOKEN` (нужна подписка Плюс). Понимает
  исполнителя, альбом, плейлист, «моя волна», «моё любимое». Работает через неофициальную
  библиотеку `yandex-music` и может сломаться, когда Яндекс что-то поменяет; как получить токен —
  в её документации: https://yandex-music.readthedocs.io/en/main/token.html. С токеном Яндекс
  Музыка становится источником по умолчанию; поменять — `JARVIS_MUSIC_SOURCE=youtube`.
- **Яндекс Станция** — если подключён Home Assistant с интеграцией YandexStation. Станции уходит
  команда «включи музыку …», играет она сама по вашей подписке. Плеер Станции находится сам
  (`media_player.yandex_station_…`) либо задаётся в `JARVIS_STATION_ENTITY`. Пауза и громкость
  Станции — обычные команды дома.
- **Тишина на время разговора.** Музыка на ПК замолкает, когда к ассистенту обратились, пока звенит
  будильник и пока звучит напоминание, и продолжает с того же места. Включённое в это время
  («включи Кино») начинает играть, когда ассистент договорит. После ответа под музыку голосовой
  клиент не ждёт продолжения разговора: иначе в «продолжение» попала бы сама музыка.
- **Ограничение.** Музыка из колонок ПК попадает в микрофон, и обращение по имени поверх неё
  распознаётся хуже. Надёжные способы — Enter в голосовом клиенте, приложение, Telegram. Лечится
  эхоподавлением или гарнитурой, это в плане.
- **Граница.** Команда Станции — единственное место, где ядро вызывает службу Home Assistant
  напрямую, а не инструмент Assist. Текст команды собирает ядро, и он всегда начинается со слов
  «включи музыку»: другую команду Алисе так не передать.
- В сценариях — шаги `music: моя волна`, `music: {query: джаз, where: station}`, `media: stop`.

## Таймеры, напоминания, будильник

Планировщик (`jarvis/schedule.py`) хранит записи в той же базе SQLite и переживает перезапуск ядра.

- «Таймер на десять минут», «напомни в шесть позвонить маме», «разбуди завтра в семь», «будильник на
  7:30 по будням», «какие таймеры стоят?», «отмени будильник». Голосом это делает Haiku одним запросом,
  из Telegram и чата — агент; инструменты общие: `schedule_set`, `schedule_list`, `schedule_cancel`,
  `schedule_dismiss`.
- Напоминание звучит один раз: сигнал и фраза. Таймер и будильник звенят, пока их не выключат, но не
  дольше 10 минут. Будильник начинает тихо и за 20 секунд набирает полную громкость.
- Выключить: сказать «стоп» или «хватит» — без обращения, пока звенит; Enter в голосовом клиенте;
  кнопка в приложении или в Telegram. Отложить: «отложи на 10 минут» или кнопка «Через 10 минут».
  Эти фразы разбираются без модели и срабатывают, только если во фразе нет ничего другого:
  «выключи свет» будильник не тронет.
- Куда приходит: на голосовой клиент (звук), в приложение, в Telegram и push через ntfy. Таймер уходит
  на телефон, только если голосовой клиент не подключён; будильник и напоминание — всегда.
- Свой звук будильника — `JARVIS_ALARM_SOUND` (wav, mp3, ogg; читается через `ffmpeg`, без него — только
  WAV). Играет его голосовой клиент, поэтому путь указывается на машине с клиентом.
- Ядро не работало в назначенное время: напоминание прозвучит при запуске с пометкой, когда оно было
  назначено; таймер и будильник, опоздавшие больше чем на 10 минут, не звенят — придёт сообщение
  «пропущен». Спящий ПК сам не проснётся.

## Сценарии

Фраза, время или кнопка запускают цепочку действий — как «Сценарии» у Алисы. Сценарий — заметка
`50_Scenarios/<название>.md` в vault (`jarvis/scenarios.py`):

```yaml
---
phrases: ["я дома", "я пришёл"]   # «Клод, я дома»
schedule: "пн-пт 07:30"           # необязательно: запуск по времени
without_name: false               # true — срабатывать и без обращения по имени
steps:
  - on: Торшер
  - off: {name: Свет, area: Зал}
  - volume: 30
  - say: С возвращением
---
```

- **Запуск фразой.** Фраза сверяется целиком и до модели: ядро начинает отвечать примерно через
  полсекунды после того, как получило фразу. Регистр, знаки и «пожалуйста» не важны; «включи кино» и «выключи кино» не путаются.
  Работает в голосе, в Telegram и в чате приложения. Если сказано другими словами («я вернулся
  домой»), сценарий по смыслу запустит Haiku — это 2–3 секунды.
- **Без обращения.** Сценарий с `without_name: true` срабатывает на фразу и без имени ассистента
  («спокойной ночи»). Только для фраз от двух слов и только со своим распознаванием: такую фразу
  может произнести и телевизор.
- **По времени.** `"07:30"` — каждый день, `"пн-пт 07:30"`, `"сб,вс 10:00"`, несколько времён —
  списком. Фразы сценария произносит голосовой клиент; если он не подключён или шаг не удался —
  придёт сообщение в Telegram и push. Ядро не работало в это время дольше десяти минут — запуск
  пропускается; правка заметки задним числом сценарий не запускает.
- **Шаги:** `on`, `off`, `home` — умный дом; `volume`, `media`, `music`, `youtube`, `open`, `notify` — компьютер;
  `timer`, `alarm`, `remind` — расписание; `say` — произнести; `ask` — поручить агенту и произнести
  его ответ (так делается утренняя сводка). Полная таблица — в `50_Scenarios/_template.md`. Шаги
  идут по порядку; если один не удался, остальные выполняются, а в конце ассистент скажет, что
  не получилось.
- **Создать голосом или в чате:** «когда я говорю „спокойной ночи“ — выключи свет в зале и поставь
  будильник на семь». Агент соберёт сценарий инструментом `scenario_save`; вы увидите шаги и
  подтвердите их в приложении или в Telegram. Напрямую заметки в `50_Scenarios/` агент не правит.
- **Границы.** Дом управляется только инструментами Assist: устройство, скрытое от ассистента в
  Home Assistant, сценарию тоже недоступно. Сайты — только http(s).
- **Приложение:** вкладка «Сценарии» — список, запуск кнопкой, включить и выключить. В Telegram —
  `/scenarios`.

## Умный дом и Notion

Оба подключения необязательны и включаются переменными в `.env`. План дальнейшего развития
(музыка, будильники, сценарии, управление ПК, свой голос) — в `docs/roadmap.md`.

### Home Assistant

```bash
docker run -d --name homeassistant --restart=unless-stopped -e TZ=Asia/Almaty \
  -v ~/.local/share/jarvis/homeassistant:/config --network=host \
  ghcr.io/home-assistant/home-assistant:stable
```

1. Откройте `http://127.0.0.1:8123`, создайте учётную запись и добавьте свои устройства.
2. Настройки → Устройства и службы → Добавить интеграцию → **Model Context Protocol Server**.
3. Профиль → Безопасность → **Long-lived access tokens** → создать токен, вписать в `.env`:
   `HASS_URL=http://127.0.0.1:8123`, `HASS_TOKEN=…`.

Агент получает инструменты `mcp__home__*`. По умолчанию ядро ходит на `/api/mcp/assist` и видит
только то, что открыто голосовым ассистентам (Настройки → Голосовые ассистенты → Открытые объекты).
`HASS_MCP_PATH=/api/mcp` открывает все API Home Assistant, включая вызов любой службы и
перезагрузку интеграций, — включайте осознанно. Замки, сигнализацию и ворота туда лучше не
добавлять: подтверждения на действия в доме пока нет. Каждое действие пишется в журнал.

В голосовом контуре те же инструменты Assist получает сам Haiku (`jarvis/home.py`), поэтому
«включи лампочку в зале» выполняется за 1–2 с без агента на Sonnet. Список устройств ядро
перечитывает раз в 5 минут. Home Assistant недоступен — команды дому идут агенту, как раньше.

### Notion

1. `notion.so/profile/integrations` → новая внутренняя интеграция → скопировать токен в `NOTION_TOKEN`.
2. На нужных страницах: ··· → Connections → подключить интеграцию. Остальное она не видит.
3. `NOTION_PARENT_PAGE` — ссылка на страницу, под которой ассистент создаёт новые (необязательно).

Инструменты: `notion_search`, `notion_read`, `notion_append`, `notion_create`. Удалять и
перезаписывать страницы ассистент не умеет. Основная память остаётся в Obsidian-vault; в Notion
ассистент пишет, только когда вы прямо его назвали.

## Приложение (этап 3)

Один Vue-клиент в `app/` для всего: окно Tauri на Windows/macOS, APK для Android и обычная
веб-страница, которую ядро раздаёт по адресу `/app/`.

- **Чат** — общий разговор из всех каналов в реальном времени: написали в Telegram — сообщение
  сразу видно в приложении. Текст уходит агенту (Sonnet), кнопка 🎙 — голосом через быстрый
  контур (Haiku) с озвучкой. Удерживать — говорить; короткое касание — «нажал, сказал, нажал».
  Нажатие во время ответа перебивает его. Кнопка ⚡ переводит в быстрый режим и текст: отвечает
  быстрая модель, вслух и за доли цента, а сложное сама передаёт агенту.
- **Функции** — что ассистент умеет и что из этого сейчас работает: у каждой функции состояние
  (работает, нужна настройка, выключено, не отвечает), подсказка, как включить, и фразы для пробы.
  ⚡ у фразы — ответит быстрая модель, 🧠 — агент; рядом написано, что произойдёт (зазвенит таймер,
  откроется вкладка). «Проверить речь» синтезирует фразу и распознаёт её обратно — без микрофона и
  колонок. Здесь же расход агента за сегодня.
- **Задачи** — запросы подтверждения с кнопками и лента действий агента (инструменты, отказы, решения).
- **Сценарии** — список сценариев из vault: шаги, запуск кнопкой, включить и выключить.
- **Проекты** — реестр из frontmatter, обновляется сам, когда агент правит заметку.
- **Настройки** — адрес ядра и токен, новый разговор.

### Подтверждения
Перезапись целиком существующей заметки в `10_Projects/`, `20_Areas/`, `30_Decisions/` агент
делает только после вашего «да». Запрос приходит сразу в приложение, в Telegram (с кнопками) и
push-напоминанием в ntfy; ответить можно где удобнее. Нет ответа 5 минут — значит «нет».
Это тот же механизм, через который на этапе 5 пойдут деплой в прод и merge.

### Запуск

```bash
cd app && npm install
npm run build              # веб-версия → app/dist, ядро раздаёт её на /app/
npm run tauri dev          # окно приложения с горячей перезагрузкой
npm run tauri build        # установщик: .msi/.exe на Windows, .dmg на macOS
```

Для `tauri build` нужен Rust (rustup), на Windows — ещё Microsoft C++ Build Tools и WebView2
(в Windows 10/11 уже есть).

### Окно на ПК: всегда наготове

На ПК оболочка Tauri добавляет то, чего веб-странице нельзя:

- **Значок в трее.** Крестик прячет окно в трей, а не закрывает программу; «Открыть» и «Выйти» —
  в меню значка. Когда звенит будильник или агент ждёт подтверждения, спрятанное окно
  показывается само.
- **Один экземпляр.** Повторный запуск показывает уже открытое окно. Так можно назначить системную
  горячую клавишу на команду `jarvis-app` (GNOME на Wayland не даёт программам перехватывать
  клавиши самим).
- **Автозапуск** при входе в систему, свёрнутым в трей (`--hidden`). Включается и выключается
  в окне: «Функции» → «Этот компьютер».
- **Подключение без ввода токена.** На машине с ядром окно читает адрес и токен из файла
  `~/.config/jarvis/env` — это ссылка на `.env` ядра (или путь в `JARVIS_ENV_FILE`). Адрес берётся
  из `JARVIS_APP_SERVER`, а если его нет — из `JARVIS_VOICE_URL`.
- **Службы** (Linux, systemd пользователя): в «Функциях» видно, работают ли ядро, распознавание и
  синтез речи, и их можно перезапустить. «Слушать имя» включает и выключает голосовой клиент
  `jarvis-voice` вместе с его автозапуском; так же — запасной голос и клон. Приложение трогает
  только службы `jarvis-*` из своего списка.

Установка на Linux для текущего пользователя (сборка, ярлык в меню, ссылка на `.env`, автозапуск):

```bash
scripts/install-desktop.sh
```

`--no-build` ставит уже собранное, `--remove` убирает программу, ярлык и автозапуск.

### Android (в том числе Huawei без Google-сервисов)

1. Android Studio с SDK и NDK; переменные `JAVA_HOME`, `ANDROID_HOME`, `NDK_HOME`;
   `rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android`.
2. `npm run tauri android init` — создаст `app/src-tauri/gen/android`.
3. В `gen/android/app/src/main/AndroidManifest.xml` добавить
   `<uses-permission android:name="android.permission.RECORD_AUDIO"/>` и
   `<uses-permission android:name="android.permission.MODIFY_AUDIO_SETTINGS"/>`.
4. `npm run tauri android build -- --apk --debug` и поставить APK на телефон.

Микрофон на Android при первом нажатии 🎙 спросит разрешение. Распознавание всё равно идёт на
сервере (SpeechKit), поэтому отсутствие Google-сервисов на Huawei не мешает.

### Доступ с телефона: Tailscale

Ядро наружу не открываем. На ПК с ядром и на телефоне — Tailscale (на Huawei — APK с
tailscale.com или F-Droid). На ПК:

```bash
tailscale serve --bg 8000
```

Получится адрес `https://<имя-пк>.<tailnet>.ts.net` — его и вписываем в настройках приложения.
HTTPS обязателен: без него браузер не даст микрофон, а Android-сборка не пустит `ws://`.
Тот же адрес с `/app/` в браузере телефона — полноценная веб-версия (можно «добавить на главный экран»).

### Push: ntfy
Поставьте приложение ntfy (APK или F-Droid — работает без GMS), подпишитесь на тему из
`NTFY_TOPIC` и отключите для ntfy оптимизацию батареи. Push приходит, когда нужно
подтверждение и когда голосовая задача доделалась в фоне. В push нет ссылок и кодов, которыми
можно что-то подтвердить: тема на ntfy.sh публичная для всех, кто знает её имя.

## HTTP API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | без авторизации |
| GET | `/status` | что умеет ассистент и что сейчас работает; расход агента за сегодня |
| POST | `/status/speech` | проверка речи: фраза синтезируется и распознаётся обратно |
| POST | `/chat` `{"text": "...", "channel": "pc"}` | ход агента |
| POST | `/session/new` | новый разговор |
| GET | `/projects` | реестр проектов (JSON) |
| GET | `/messages?limit=100` | общий разговор из всех каналов |
| GET | `/journal?limit=50` | последние записи журнала |
| GET | `/confirmations` | ожидающие подтверждения |
| POST | `/confirmations/{id}` `{"approve": true}` | ответить на подтверждение |
| GET | `/schedule` | активные таймеры, напоминания и будильники |
| POST | `/schedule/{id}/stop` | выключить то, что звенит |
| POST | `/schedule/{id}/snooze` `{"minutes": 10}` | отложить |
| DELETE | `/schedule/{id}` | отменить |
| GET | `/scenarios` | сценарии из vault |
| POST | `/scenarios/{название}/run` | запустить сценарий |
| POST | `/scenarios/{название}/enabled` `{"enabled": false}` | включить или выключить |
| WS | `/events/ws` | живая лента: реплики, инструменты, подтверждения, срабатывания |
| WS | `/voice/ws` | голосовой протокол (описан в `jarvis/voice.py`) |

Все, кроме `/health`, требуют `Authorization: Bearer $JARVIS_API_TOKEN` (WebSocket — также `?token=`).
Токен из адреса WebSocket в журнал ядра не попадает: вместо него пишется `token=***`.
