# Smart Home OS поверх Jarvis: что можем сделать

на этой машине и в этом доме, чего пока не из чего делать. По правилу 6.1 задания — сначала схема
потоков, модель данных, выбор архитектуры и задачи этапа 1. Владелец согласился 20.11.2026; что из
этапа 1 сделано — в разделе 6.

## 2. Чего нет на машине и в доме

- **Устройств под половину задания:** в Home Assistant нет камер, климата, ИБП, счётчиков по линиям;
  датчик присутствия один и недоступен. Разделы «Климат», «Энергетика», «Камеры», поиск по кадрам и
  зональную озвучку по присутствию не на чем ни сделать, ни проверить.
- **MQTT** в Home Assistant нет. Телеметрию ПК можно отдавать и без него — через REST Home Assistant.
- **Wake-on-LAN** не имеет смысла: Home Assistant работает в Docker на этом же ПК.
- **Flutter, Dart, adb** не установлены. Мобильное приложение на Flutter — отдельный проект на недели.
- **Локальная модель:** Ollama нет, но на машине уже работает стек `localnexus` (llama-server и LiteLLM)
  и занимает 3,6 из 6 ГБ видеопамяти. Годится ли его модель для вызова инструментов по-русски
  быстрее секунды — не проверено.
- **Интеграции `ha-mcp`, `ha-llmvision`, `yandex_smart_home`** не стоят. Вместо `ha-mcp` работает
  встроенный MCP-сервер Home Assistant.

## 3. Решение по архитектуре

Вариант A, с тремя отступлениями от задания:

1. **Приложение ходит в дом через ядро Jarvis, а не напрямую в Home Assistant.** Токен Home Assistant
   остаётся в одном месте, на телефон не попадает; права, журнал действий и подтверждения уже в ядре.
   Ядро держит одно соединение WebSocket с Home Assistant и раздаёт изменения клиентам.
2. **Flutter откладываем.** Клиент на Vue уже открывается с телефона и собирается в APK через Tauri.
   Сначала доводим интерфейс на ПК и в браузере телефона; Flutter — когда станет ясно, чего не хватает
   веб-клиенту (фоновые датчики, вибрация, киоск).
3. **Репозиторий не переименовываем** в `apps/`, `services/`: перенос ничего не даёт пользователю.
   Токены оформления — общий JSON в `app/src/tokens.json`, из него CSS-переменные; для Flutter его
   можно будет экспортировать в Dart.

## 4. Потоки данных

```text
 Home Assistant (Docker, 127.0.0.1:8123)
   ▲  REST: команды /api/services, шаги добавления устройств
   │  WebSocket: реестры комнат и устройств, подписка state_changed
   ▼
 Ядро Jarvis (FastAPI, 127.0.0.1:8010) ── быстрая модель / агент ── MCP-сервер Home Assistant
   │  кэш состояний в памяти, журнал, права профиля, подтверждения
   │  /home (снимок)   /events/ws: {type:"home", entity_id, state…}   POST /home/entity/{id}
   ▼
 Клиент Vue (окно Tauri, браузер телефона)
   │  хранилище: комнаты → устройства; очередь команд с откатом; кэш последнего снимка
   ▼
 Оболочка Tauri (Rust): трей, быстрое окно, телеметрия ПК → ядро → датчики в Home Assistant
```

Команда: плитка меняется сразу → `POST /home/entity/{id}` → ядро вызывает службу → Home Assistant
присылает `state_changed` → ядро рассылает событие → клиент снимает отметку «ждёт». Ошибка или нет
подтверждения 5 секунд — плитка возвращается и показывает причину.

## 5. Модель данных

```ts
type Domain = "light" | "switch" | "climate" | "cover" | "media_player" | "sensor" | "binary_sensor" | "button" | "scene";

interface Entity {           // строка вкладки; сырой идентификатор в интерфейс не выводится
  id: string;                // entity_id — только как ключ
  domain: Domain;
  name: string;
  room: string;
  device: string;
  available: boolean;
  on: boolean | null;
  level?: number;            // яркость, громкость или положение, 0–100
  value?: string;            // показание датчика
  unit?: string;
  voice: boolean;            // открыто голосовому ассистенту
  updated: number;           // время последнего события от Home Assistant
}

interface Command {          // очередь команд с откатом
  id: number;
  entity: string;
  action: "on" | "off" | "toggle" | "level" | "temperature" | "play_pause";
  value?: number;
  before: Pick<Entity, "on" | "level">;   // к чему вернуться при ошибке
  sent: number;
  state: "pending" | "confirmed" | "failed";
  error?: string;
}

interface Pill { kind: "light" | "climate" | "power" | "pc" | "alert"; text: string; count: number; filter: string; }
type Profile = "admin" | "resident" | "simple";
```

## 6. Этап 1: задачи

Размер: **М** — до дня, **С** — два-три дня.

**Сделано 20.11.2026** (ветка `reliability`, не закоммичено):

| № | Задача | Что проверено |

## 7. Этапы 2 и 3: что возможно

- **Можно сделать на этой машине:** телеметрия ПК и датчики «микрофон занят», «камера занята»,
  «простой» в Home Assistant; сон, блокировка и переключение звукового выхода с подтверждением;
  пауза Станции, когда на ПК идёт звонок; генератор автоматизаций с показом и подтверждением перед
  сохранением; аналитик, который раз в час смотрит дом и предлагает действие; отмена последней команды
  в чате.
- **Ждёт устройств:** климат, энергия и ИБП, камеры и поиск по кадрам, зональная озвучка по
  присутствию, план дома со слоями.
- **Ждёт решения:** Flutter для телефона и планшета; локальная быстрая модель из стека `localnexus`.
